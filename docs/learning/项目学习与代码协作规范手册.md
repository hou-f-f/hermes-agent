## 1. 规范编制背景与宗旨

Hermes Agent 作为一款前沿的开源个人 AI Agent 架构，其内部融合了**前缀缓存优化（Prompt Caching）**、**跨进程分布式轮次租约（Turn Lease）**、**多阶段解耦状态机（_LoopState）**、**工具分段安全调度（SegmentPlanner）** 以及 **三级上下文动态压缩** 等大量复杂的系统级工程机制。

在以往的学习与代码阅读中，往往存在两个核心痛点：
1. **官方文档滞后脱节**：官方线上文档长期停留在 15k+ 行单文件时代，与 2026 年 9 月完成的 Facade + Siblings 现代模块化拓扑严重脱节；
2. **源码注释机翻失真**：纯文本字面机翻缺乏架构上下文，既看不懂代码意图，又破坏了原本英文字节稳定性。

为了让团队能够**系统性、高质量、可持续地深入吃透** Hermes Agent 的每一行核心源码，特制定本套《项目学习与代码协作规范手册》。

## 2. 源码变更与双语注释规范（中英双语 + 深度解析）

在阅读、重构或为项目核心源码添加中文注释时，必须严格执行以下**四项铁律**：

### 2.1 中文在前，原版英文完整保留在后
- **结构范式**：
  ```python
  def some_core_function(agent, ...):
      """【中文功能定位与模块职责说明】
      此处撰写高可读性、结合 Hermes 运行时的中文深入讲解：
      1. 阐明该函数的调用时机与上下文生命周期；
      2. 解释关键参数的作用与边界条件；
      3. 说明涉及的性能考虑、设计不变量或异常自愈逻辑（如针对特定 issue 的修复方案）。

      Original English docstring follows verbatim:
      Original English explanation and technical details...
      """
  ```
- **禁止破坏**：**绝对禁止**直接覆盖或删除原有的英文 Docstring 与设计作者注释，必须保持中英文双语完整对照。

### 2.2 拒绝生硬机翻，深度融入架构意图
- 所有的中文注解**严禁无意义的字面直译**，必须基于对整个项目的底层运作机制的深度理解。
- 关键术语必须准确映射其工程内涵：
  - `Prompt Caching is sacred` $\rightarrow$ 前缀缓存神圣不可侵犯（长对话降低成本与延迟的核心）
  - `Durable Turn Lease` $\rightarrow$ 跨进程持久化排他轮次租约（防止 CLI/Web/Desktop 多端并发冲突）
  - `SegmentPlanner` $\rightarrow$ 工具分段执行调度器（区分只读并发段与串行屏障段）
  - `Micro-compaction` $\rightarrow$ 后置微压缩（针对工具超长输出的局部在位剪裁）
  - `Native Responses Compaction` $\rightarrow$ 原生 Responses API 压缩检查点

### 2.3 必须追加代码讲解与设计原理
- 不仅要翻译“这段代码做了什么”，更要讲清楚“**为什么必须这么做**”。
- 例如：
  - 为什么工具 ID 碰撞消解必须使用 `_d<n>` 后缀而严禁使用 `uuid4`？（因为随机 UUID 会改变请求 Token，破坏大模型的前缀缓存）。
  - 为什么被打断的轮次绝对禁止向外部向量数据库同步？（因为残缺的交互上下文会永久污染用户的长期经验库）。

### 2.4 代码修改后必自测编译
- 每次在 Python 文件中注入中文注释后，必须在终端执行：
  ```bash
  python3 -m py_compile <modified_file.py>
  ```
  只有退出码为 0、确认零语法错误后，方可提交。

## 3. 学习手册生成与目录结构规范

### 3.1 目录组织与中文命名原则
- 所有系统性学习输出统一归档在项目根目录的 **`docs/learning/`** 下。
- **章节子文件夹必须使用中文命名**，前缀标注两位序号：
  ```text
  docs/learning/
  ├── README.md                                    # 学习路线与总索引导航
  ├── 项目学习与代码协作规范手册.md                   # 本规范说明书
  ├── 01_Hermes Agent Loop 内部机制深度学习手册/     # 第一章（已完成）
  │   ├── agent_loop_internals_manual.md          # 核心机制深度学习手册
  │   └── agent_loop_visualizer.html              # 交互式架构可视化组件
  ├── 02_提示词工程与前缀缓存保活/                   # 第二章（规划中）
  ├── 03_工具分段规划与安全调度/                     # 第三章（规划中）
  ├── 04_上下文压缩与微压缩体系/                     # 第四章（规划中）
  └── ...
  ```

### 3.2 学习手册标准内容结构
每个学习专题的手册（Markdown）必须遵循以下结构大纲：
1. **架构演进背景**：对比官方旧版实现或文档断层，讲透为何重构；
2. **现代模块拓扑与职责划分**：梳理各模块交互关系与职责表；
3. **流程可视化图解**：
   - 必须使用 **高对比度现代配色方案的 Mermaid 流程图**（包含用户层、门禁层、状态机驱动层、各独立阶段、分支与持久化）；
   - 核心复杂模块建议配套产出独立的交互式 HTML 可视化组件；
4. **生命周期核心阶段逐行/逐段拆解**：梳理从输入到输出的每个执行 Phase；
5. **系统级核心设计不变量（Invariants）**：提炼本模块必须坚守的工程原则；
6. **官方旧文档 vs 现代源码对照表**：打脸旧概念，树立新认知；
7. **重点源码导读路径**：为初学者梳理最高效的阅读顺序。

## 4. Git 远程仓库与提交推送纪律

### 4.1 远程仓库绑定规范
本项目为官方仓库的独立 Fork，通过 `git remote -v` 明确以下边界：
- **`origin`** $\rightarrow$ `https://github.com/hou-f-f/hermes-agent.git`
  - 团队的日常工作仓库，所有的代码注释、重构、学习手册及文档均提交并推送到这里。
- **`upstream`** $\rightarrow$ `https://github.com/NousResearch/hermes-agent.git`
  - 官方只读上游，用于持续跟踪官方主线的新特性与 Bugfix。

### 4.2 GitHub 局部代理环境维护
针对国内网络直连 GitHub 容易出现握手重置（`Connection reset by peer`）的问题，已在 Git 本地配置了定向代理：
```bash
git config --local http.https://github.com.proxy http://127.0.0.1:6789
```
*注：该配置仅对 `https://github.com` 生效，不影响本地服务或内网环境。团队成员在日常操作时请确保本地代理端口开启。*

### 4.3 日常提交与同步命令速查
- **推送到个人/团队 Fork 仓库**：
  ```bash
  git add .
  git commit -m "docs(learning): add chapter 01 agent loop manual"
  git push origin main
  ```
- **同步官方主线更新**：
  ```bash
  git fetch upstream
  git merge upstream/main   # 或使用 git rebase upstream/main
  ```

## 5. 四大核心系统级设计不变量（工程红线）

在后续的学习与任何代码调整中，全体成员与 AI 智能体必须牢记以下**四大不变量**，绝不能为了“代码好看”或“偷懒”而破坏：

```
┌──────────────────────────────────────────────────────────────────────────────┐
│                        Hermes Agent 四大设计不变量                           │
├──────────────────────────────────────────────────────────────────────────────┤
│ 1. Prompt Caching is Sacred     │ 前缀缓存神圣不可侵犯：Prompt 字节级不变，   │
│                                │ 工具顺序严格冻结，界面切换追加尾部注记。    │
├──────────────────────────────────────────────────────────────────────────────┤
│ 2. Durable Turn Lease           │ 跨进程持久化轮次租约：单会话并发互斥，      │
│                                │ 看门狗心跳防死锁，拒绝脏写与竞态。          │
├──────────────────────────────────────────────────────────────────────────────┤
│ 3. Memory Sync Invariant        │ 记忆同步安全守卫：被打断或不完整的轮次      │
│                                │ 绝对禁止同步外部向量库，严防记忆污染。      │
├──────────────────────────────────────────────────────────────────────────────┤
│ 4. Segment Planner Concurrency │ 工具安全分段执行：并发安全只读并行，        │
│                                │ 写入与交互串行屏障，严格保证副作用确定性。  │
└──────────────────────────────────────────────────────────────────────────────┘
```
